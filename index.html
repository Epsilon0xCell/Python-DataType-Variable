Folio 1The collected specimen

I wrote one program for this repo, variable.py, and it holds exactly one value. So the ledger opens with exactly one collected specimen. Everything about it below is copied from the file or read off a run of it.

Entry No. 1 In variable.py

str text, kept in quotes

Example value, as written in the file
keys = "fun"
type() result, stamped from a run
<class 'str'>
How it behaves
It holds text. I can read its letters by position, "fun"[0] is 'f' and len("fun") is 3, and I cannot change a letter in place once the string exists.

The file in full is six lines, four of them a comment I wrote to say what the two working lines mean. Here it is as a transcription, line numbers included, checked against the file at the head of this repo:

1 | # The smallest useful Python program: bind a value to a name, then use
2 | # the name. "keys" holds a str here; the same name could hold an int or a
3 | # list later, because Python variables are labels on values, not typed
4 | # boxes. print() shows the value the label currently points at.
5 | keys = "fun"
6 | print(keys)

$ python3 variable.py

fun

That is the complete output. One word and a newline, exit code 0. I ran it again while rebuilding this page and it printed the same four bytes.

Folio 2Field notes on the other types

The comment at the top of variable.py says the same name could hold an int or a list later. That sentence is why this folio exists. The eight entries below are my notes on the built-in types a beginner meets first. None of them are in variable.py, and I am not going to pretend they are. Each example value is real, each stamp is the type() result I got when I ran it, and each behaviour line is one thing I checked, not a paragraph copied out of a textbook.

Entry No. 2 Field note

int whole numbers

Example value
42
type() result
<class 'int'>
How it behaves
It holds whole numbers with no decimal part, so 42 // 5 comes out as 8 and the remainder is simply not in the answer.

Entry No. 3 Field note

float numbers with a decimal part

Example value
3.5
type() result
<class 'float'>
How it behaves
It keeps the decimal part through arithmetic, so 3.5 * 2 comes out as 7.0, not 7.

Entry No. 4 Field note

bool one of two answers

Example value
True
type() result
<class 'bool'>
How it behaves
It holds True or False and nothing else, and Python still counts it as a number: True + 1 comes out as 2.

Entry No. 5 Field note

list items in order, changeable

Example value
[1, 2, 3]
type() result
<class 'list'>
How it behaves
It holds items in order and lets me change it after I make it, so after append(4) the example above reads [1, 2, 3, 4].

Entry No. 6 Field note

tuple items in order, fixed

Example value
(1, 2)
type() result
<class 'tuple'>
How it behaves
It holds items in order like a list, I read (1, 2)[0] as 1, and I cannot change an item once the tuple is made.

Entry No. 7 Field note

dict values filed under keys

Example value
{"a": 1}
type() result
<class 'dict'>
How it behaves
It stores pairs, so I fetch a value by its key instead of its position: {"a": 1}["a"] gives 1.

Entry No. 8 Field note

set each item once

Example value
{1, 2}
type() result
<class 'set'>
How it behaves
It holds each item once, so writing {1, 2, 2, 3} keeps only 1, 2, and 3. The second 2 never makes it into the book.

Entry No. 9 Field note

NoneType the empty place

Example value
None
type() result
<class 'NoneType'>
How it behaves
It has exactly one value, None. I use it when a name has to exist before it has a real value to point at.

Folio 3The label moves, the book proves it

The claim in the file header is that a variable is a label, not a typed box. I checked it with a short scratch script that rebinds the name keys and asks for its type after each binding. This script is not in the repo. It is a check I ran on the repo claim, and I labeled it that way here.

keys = "fun"
print(type(keys).__name__)
keys = 42
print(type(keys).__name__)
keys = [1, 2]
print(type(keys).__name__)
str
int
list

Same name, three types, no error. That is the whole lesson of this repo, shown instead of just stated.

Folio 5Why the book is thin

I could have filled this repo with one file per type and called it a course. I did not, because the point I wanted to keep was the smallest one: a name, a value, and a print. Two working lines carry that point with nothing left over, so I left the repo at two working lines and wrote my notes on the other types here, labeled as notes.

If you run one thing from this page, run python3 variable.py and watch it print fun. Then change "fun" to 42 in your own copy and run it again. The label does not care. That is the entry this whole ledger exists to record.
